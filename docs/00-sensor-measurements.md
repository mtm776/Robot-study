# 0. IMU와 2D LiDAR는 어떤 값을 보내나요?

이 노트에서는 센서 모델과 관계없이 읽을 수 있도록 ROS 2 Jazzy의 표준 메시지를 기준으로 설명합니다. 실제 토픽 이름과 측정 주기는 드라이버 설정에 따라 달라집니다. 아래 값은 동작을 이해하기 위한 예시입니다.

| 센서 | 메시지 하나에 담기는 것 | 예시로 확인할 값 |
|---|---|---|
| 관성 측정 장치(IMU) | 한 시각의 각속도와 가속도. 드라이버가 제공하면 방향 추정값도 포함 | `angular_velocity.z` · 위쪽 축을 중심으로 얼마나 빠르게 회전하는지 |
| 2D LiDAR | 여러 광선의 거리 배열과 광선의 방향·시각을 계산하는 데 필요한 정보 | `ranges[2]` · 세 번째 광선이 읽은 거리 |

## 1. IMU · 한 메시지의 x, y, z는 같은 시각의 서로 다른 축

| 필드 | 들어오는 값 | 의미 |
|---|---|---|
| `header.stamp` | 시각 | 드라이버가 이 샘플에 붙인 시각. 센서 측정 시각을 어떻게 기록하는지는 드라이버에서 확인합니다. |
| `header.frame_id` | 좌표계 이름 | 아래 x, y, z의 방향을 정하는 좌표계입니다. 예를 들어 `imu_link`입니다. |
| `angular_velocity.x/y/z` | 각속도 3개, rad/s | 각 축 **주위로** 도는 속도입니다. 예를 들어 z축이 로봇 위쪽과 일치하면 z 성분은 수평 회전 속도입니다. |
| `linear_acceleration.x/y/z` | 가속도 3개, m/s² | 각 축 **방향의** 가속도계 출력입니다. 중력을 제거하지 않은 가속도계 출력에서는 정지해도 위쪽 축에 약 +9.81 m/s²가 나타날 수 있습니다. |
| `orientation.x/y/z/w` | 쿼터니언 4개 | 센서 또는 드라이버가 제공하는 방향 추정값입니다. 각속도처럼 축별 세 숫자로 읽는 필드와 표현법이 다릅니다. |
| `*_covariance` | 필드마다 9개 | 측정이나 추정의 불확실성을 나타냅니다. 메시지 정의상 행렬이 전부 0이면 공분산을 모른다는 뜻이며, 첫 값이 −1이면 해당 그룹의 추정값을 제공하지 않는다는 뜻입니다. |

[ROS 2 Jazzy Imu 메시지 정의](https://raw.githubusercontent.com/ros2/common_interfaces/jazzy/sensor_msgs/msg/Imu.msg) · [ROS IMU 데이터 규약](https://www.ros.org/reps/rep-0145.html)

### 자이로 메시지 세 개에서 z만 뽑아 보기

IMU의 +z가 로봇의 위쪽을 향하고, 자이로 샘플이 10 ms마다 들어온다고 가정합니다. 시각은 첫 메시지 기준 상대 시간입니다.

| 시각 | 해당 메시지의 각속도 (x, y, z), rad/s | z를 °/s로 환산 |
|---:|---|---:|
| 0 ms | (0.0002, 0.0001, −0.001047) | −0.06 |
| 10 ms | (−0.0001, 0.0003, +0.000349) | +0.02 |
| 20 ms | (0.0001, −0.0002, +0.052360) | +3.00 |

rad/s에 $180/\pi$를 곱하면 °/s가 됩니다. 한 메시지의 x, y, z를 가로로 읽으면 **한 시각의 세 축**이 보입니다. 여러 메시지에서 z만 세로로 뽑으면 **같은 축의 시간 변화**가 보입니다. [3장 이상치 예시](03-sensor-noise.md)는 오른쪽 열처럼 뽑은 z 성분의 기록입니다. 각속도를 시간에 걸쳐 적분하면 로봇이 실제로 얼마나 돌았는지 추정할 수 있습니다.

## 2. 2D LiDAR · 한 메시지에 여러 광선의 거리가 들어옵니다

| 필드 | 단위 | 의미 |
|---|---|---|
| `header.stamp` | 시각 | 첫 번째 광선의 측정 시각입니다. |
| `header.frame_id` | 좌표계 이름 | 광선의 방향과 이후 계산할 좌표의 기준입니다. 예를 들어 `laser`입니다. |
| `angle_min`, `angle_max` | rad | 스캔의 시작과 끝 각도입니다. 메시지 정의상 0은 센서의 +x 방향입니다. |
| `angle_increment` | rad | 인접 광선 사이 각도 간격입니다. |
| `time_increment` | s | 인접 광선 사이 측정 시간 간격입니다. |
| `scan_time` | s | 스캔과 다음 스캔 사이의 시간입니다. |
| `ranges[i]` | m | i번째 광선 방향으로 센서가 읽은 거리입니다. 유효한 거리의 범위는 `range_min`, `range_max`에 있습니다. |
| `intensities[i]` | 센서별 단위 | 반사 신호의 세기입니다. 센서가 제공하지 않으면 배열이 비어 있을 수 있습니다. |

[ROS 2 Jazzy LaserScan 메시지 정의](https://raw.githubusercontent.com/ros2/common_interfaces/jazzy/sensor_msgs/msg/LaserScan.msg)

### 거리 배열에서 한 점 읽기

세 광선만 있는 단순한 스캔을 가정합니다. 예제에서는 보기 쉽게 각도를 도로 표시합니다. 메시지에는 라디안으로 들어옵니다. 첫 각도는 −30°, 각도 간격은 30°, 시간 간격은 5 ms입니다.

| 배열 인덱스 i | 첫 광선 기준 시각 | 센서 정면 기준 각도 | 거리 |
|---:|---:|---:|---:|
| 0 | 0 ms | −30° | 1.80 m |
| 1 | 5 ms | 0° | 1.90 m |
| 2 | 10 ms | +30° | 2.00 m |

`ranges[2]`는 같은 스캔의 세 번째 광선이 10 ms에 +30° 방향에서 읽은 **2.00 m**입니다. 점을 그리려면 거리와 각도로 $(x,y)=(r\cos\alpha,r\sin\alpha)$를 계산합니다. 이 점은 LiDAR 기준 $(2\cos30^\circ,2\sin30^\circ)\approx(1.73,1.00)$ m입니다. [1장](01-coordinate-frames.md)에서는 이 좌표를 로봇 좌표로 바꿉니다.

두 센서가 공통 시각을 쓰고 있다면, 5 ms에 찍힌 LiDAR 광선에는 0 ms와 10 ms 자이로 샘플을 이용해 그때의 회전 정보를 추정할 수 있습니다. [2장](02-time-sync-and-deskew.md)에서는 각 점을 같은 시각의 로봇 축으로 표현하는 데 이 정보를 사용합니다.
